#자동 생성 검증 리포트

원본 매뉴얼 36개와 JSP 샘플 21종을 파싱해 통합하는 과정에서 발견된 항목입니다. GitBook 공개 전에 해소해야 하는 것부터 순서대로 정리했습니다.

#1. 필드명 표기 불일치 (우선순위 높음)

필드내용
TAXFREEAMOUNT와 LGD_TAXFREEAMOUNT 가 동시에 존재합니다. 같은 필드로 보이며 표기 통일이 필요합니다.
seqno는 LGD_ 접두사가 없습니다. 확인이 필요합니다.
service_type는 LGD_ 접두사가 없습니다. 확인이 필요합니다.
authdata는 LGD_ 접두사가 없습니다. 확인이 필요합니다.

HTTPS API 문서에만 등장하는 소문자 파라미터 26건(dlvtype, rcvname, seqno 등)은 XPayClient가 아닌 별도 호출 규격이므로 LGD_ 접두사가 없는 것이 정상입니다. 위 표에서 제외했습니다.

#2. 최대길이 불일치

#4. 필수 여부

결제연동스펙_표준창_v1.0.2의 셀 배경색 표기에서 추출했습니다. 빨강은 필수, 파랑은 선택입니다. 결제수단 열에만 표기된 항목은 조건부 필수로 처리했습니다.

표준창 스펙에 등장하지 않는 파라미터는 미정으로 남아 있습니다. 특히 결제창 제어용 파라미터는 매뉴얼 설명상 실질적으로 필수인데 스펙에 누락되어 있습니다.

파라미터매뉴얼 설명에서 추정되는 필수성
CST_PLATFORMtest 또는 service 중 하나를 반드시 넘겨야 초기화됩니다.
CST_MIDLGD_MID 생성에 사용됩니다.
LGD_WINDOW_TYPEPC는 iframe, 모바일은 submit 고정값입니다.
LGD_DOMAIN_URL매뉴얼에 TLS 1.2 결제창 호출을 위한 필수 파라미터로 명시되어 있습니다.
LGD_CUSTOM_PROCESSTYPE고정값 TWOTR이며 스펙 비고에 자동세팅으로 적혀 있습니다.
LGD_VERSION매뉴얼에 수정·삭제 금지로 명시되어 있으나 누락해도 동작한다고 적혀 있습니다.

#5. 구조적 발견

  • PaymentByKey 하나를 14개 문서가 공유합니다. 실제 구분자는 LGD_WINDOW_TYPE(통결창/자체창)과 LGD_PAYTYPE(결제수단)입니다.
  • CardAuth를 4개 문서가 공유합니다. 비인증은 LGD_PAN, 빌링은 LGD_BILLKEY로 갈립니다.
  • 통합결제창의 인증 응답은 10개 문서에서 완전히 동일합니다(6개 필드).
  • 상품권·휴대폰결제는 결제창 호출 시 추가 요청 파라미터가 없습니다.
  • PC와 모바일 차이는 앱카드 연동 파라미터뿐이라 페이지를 분리하지 않고 모바일 전용 배지로 처리했습니다.
  • LGD_CARDNOINTYN이 카드 승인 응답 표에 두 번 등장하며 설명이 서로 다릅니다. LGD_CARDNOINTEREST_YN과 혼동된 것으로 보입니다.

#6. 샘플 코드 대조 결과

제공된 JSP 샘플 21종을 파싱해 문서와 대조했습니다. 아래는 매뉴얼에는 없고 샘플에만 있던 내용으로, 문서에 반영했습니다.

  • 실제 클래스 경로는 lgdacom.XPayClient.XPayClient입니다.
  • 해쉬는 직접 MD5로 계산하지 않고 xpay.GetHashData(LGD_MID, LGD_OID, LGD_AMOUNT, LGD_TIMESTAMP)를 호출합니다. 상점키는 라이브러리가 mall.conf에서 읽으므로 코드에 넣지 않습니다.
  • 타임스탬프는 xpay.GetTimeStamp()로 생성합니다.
  • 통신 응답코드(xpay.m_szResCode)와 거래 응답코드(LGD_RESPCODE)는 별개입니다. 두 값이 모두 0000이어야 결제 성공입니다.
  • 상점 DB 처리 실패 시 xpay.Rollback(사유)으로 자동취소해야 합니다.
  • 샘플 인코딩은 EUC-KR입니다. UTF-8 환경에서는 mall.conf의 output_UTF8=1이 필요합니다.
