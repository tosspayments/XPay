#가맹점 서버 보안 점검

결제 연동 전에 아래 항목을 확인해주세요. 특히 설정 파일 배치는 상점키 노출과 직결되므로 반드시 점검해야 합니다.

#설정 파일과 로그 배치

가장 중요한 항목입니다. mall.conf 에는 운영용 상점 ID(MID)와 상점키(mertkey)가 저장됩니다. 이 값이 노출되면 제3자가 결제 취소를 포함한 거래를 요청할 수 있습니다.

mall.conf 와 log_dir 은 웹에서 접근할 수 없는 경로에 두어야 합니다. log_dir 에는 승인 요청과 승인 결과의 송수신 로그가 저장되므로 이 역시 결제 관련 중요 정보입니다.

#웹에서 접근 가능한 경로 (여기에 두면 안 됩니다)

환경웹 접근 가능 경로
PHP + ApacheDOCUMENT_ROOT 이하
Java (JSP)CONTEXT ROOT 이하
ASP · ASP.NET + IISwwwroot 이하

#점검 방법

브라우저에서 아래 주소로 접근했을 때 파일 내용이 보이면 잘못 배치된 상태입니다.

text
https://내가맹점도메인/lgdacom/conf/mall.conf

403 Forbidden 또는 404 Not Found 가 나와야 정상입니다. 내용이 보이면 즉시 경로를 옮기고 상점키 재발급을 요청하세요.

자세한 배치 방법은 conf 설정을 참고하세요.

#상점키 사용 원칙

  • 상점키는 서버에서만 사용합니다. HTML, JavaScript, 앱 코드에 넣지 마세요.
  • 해쉬 생성도 서버에서 수행합니다. xpay.GetHashData() 를 쓰면 라이브러리가 mall.conf 에서 상점키를 읽으므로 코드에 값을 적을 필요가 없습니다. 자세한 내용은 해쉬데이터 생성을 참고하세요.
  • 테스트 상점키와 운영 상점키를 구분해 관리하세요.
  • 압축 파일 비밀번호나 상점키를 문서·폴더명·저장소에 평문으로 남기지 마세요.

#HTTP 프로토콜

#HTTPS만 사용해주세요

토스페이먼츠 API는 HTTPS로 호출해야 합니다.

HTTPS는 HTTP의 보안(Secured) 버전입니다. HTTP로 주고받는 데이터는 암호화되지 않은 평문(plaintext)이기 때문에 개인 정보가 유출될 수 있습니다. 따라서 구매자의 결제 정보와 개인 정보를 보호하는 보안을 강화한 프로토콜인 HTTPS를 사용해야 합니다.

#TLS 1.2 이상만 지원합니다

TLS(전송 계층 보안)은 안전한 통신 프로토콜입니다. 토스페이먼츠 API는 TLS 버전 1.2 이상만 지원합니다.

TLS 1.2 미만의 SSL/TLS 버전은 보안이 취약하여 지원하지 않습니다. 상점 서버의 HTTP 클라이언트 환경이 TLS 1.2 이상을 지원하는지 확인해주세요.

언어별로 TLS 1.2를 쓰기 위한 최소 버전 요건이 있습니다. 설치 및 환경 구성에서 확인하세요.

#안전한 Cipher Suite를 사용해주세요

아래의 Cipher Suite 또는 이보다 보안이 강한 알고리즘만 지원됩니다.

Cipher Suite(사이퍼 스위트) TLS/SSL 통신에서 키 교환·암호화·무결성 검사에 어떤 알고리즘을 조합해 쓸지 정해 놓은 세트입니다.

TLS 1.3

  • TLS_AES_128_GCM_SHA256
  • TLS_AES_256_GCM_SHA384
  • TLS_CHACHA20_POLY1305_SHA256

TLS 1.2

  • ECDHE-ECDSA-AES128-GCM-SHA256
  • ECDHE-RSA-AES128-GCM-SHA256
  • ECDHE-ECDSA-AES128-SHA256
  • ECDHE-RSA-AES128-SHA256
  • ECDHE-ECDSA-AES256-GCM-SHA384
  • ECDHE-RSA-AES256-GCM-SHA384
  • ECDHE-ECDSA-AES256-SHA384
  • ECDHE-RSA-AES256-SHA384

#응답 위조 검증

결제 응답을 받으면 LGD_HASHDATA 를 재계산해 응답값과 일치하는지 확인해야 합니다. 값이 다르면 위조된 응답이므로 결제를 성공으로 처리하지 마세요.

검증 방법은 해쉬데이터 생성의 응답 해쉬 항목을 참고하세요.

#방화벽 설정

결제 API 호출과 가상계좌 입금통보 수신을 위해 방화벽에 IP를 허용해야 합니다. 대상 IP는 방화벽 및 IP 정보를 참고하세요.

가상계좌 입금통보(LGD_CASNOTEURL)는 표준 포트만 사용할 수 있습니다. HTTP는 80, HTTPS는 443 이외의 포트로는 통보를 수신할 수 없습니다.
