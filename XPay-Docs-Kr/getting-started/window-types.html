#연동 방식 선택

토스페이먼츠 결제는 네 가지 방식으로 연동할 수 있습니다. 어느 방식을 쓰는지에 따라 호출하는 화면과 전달하는 파라미터가 달라지므로, 연동을 시작하기 전에 먼저 결정해야 합니다.

방식결제창 제공 주체특징
통합결제창토스페이먼츠결제수단 선택 화면까지 제공받습니다. 가장 일반적인 방식입니다.
자체창카드사·간편결제사개별 카드사 자체창 또는 간편결제를 직접 호출합니다.
API 형없음 (가맹점 페이지)결제창 없이 가맹점 화면에서 입력받아 처리합니다.
기타방식별로 다름별도 URL 호출 또는 라이브러리로 제공되는 서비스입니다.

#통합결제창 (통결창)

토스페이먼츠가 제공하는 통합결제창을 이용하여 결제하는 방식입니다.

구매자가 결제창에서 결제수단을 선택하고 인증을 마치면 LGD_PAYKEY가 발급되고, 이 키로 승인을 요청합니다. 결제수단 선택 화면과 각 결제수단의 인증 화면을 토스페이먼츠가 모두 제공하므로 가맹점이 구현할 화면이 가장 적습니다.

PC는 iframe으로, 모바일은 페이지 이동 방식으로 열립니다. 이 차이는 LGD_WINDOW_TYPE으로 지정합니다.

환경LGD_WINDOW_TYPE
PCiframe
모바일submit

연동 문서는 통합결제창 결제를 참고하세요. 카드, 계좌이체, 가상계좌, 상품권, 휴대폰결제를 한 페이지에서 다룹니다.

#자체창 (허브형)

토스페이먼츠가 제공하는 통합결제창을 사용하지 않고 개별 카드사 자체창 또는 간편결제를 직접 호출하는 방식입니다.

결제수단 선택 화면을 가맹점이 직접 구성하고, 선택된 카드사의 결제창을 바로 띄웁니다. 결제수단 선택 UI를 가맹점 디자인에 맞추고 싶을 때 사용합니다.

통합결제창과 인증 이후 승인 흐름은 동일하지만, LGD_CARDTYPE, LGD_SP_CHAIN_CODE, LGD_EASYPAY_TRANTYPE 같은 자체창 전용 파라미터를 추가로 전달해야 합니다.

연동 문서는 자체창 결제를 참고하세요.

구 자체창 방식은 지원이 종료되었습니다. 신규 연동은 TWOTR 방식을 사용하며, 자세한 내용은 자체창 결제 문서에 정리되어 있습니다.

#API 형

토스페이먼츠의 결제창을 사용하지 않고, 필요한 정보를 가맹점 페이지에 직접 입력하여 처리하는 방식입니다.

결제창이 없으므로 카드번호·유효기간·비밀번호 앞 2자리 같은 정보를 가맹점이 직접 입력받아 전달합니다. 취소나 환불처럼 구매자 화면이 필요 없는 기능도 이 방식에 해당합니다.

카드번호를 직접 입력받는 방식이므로 가맹점 서버의 보안 요건이 더 엄격합니다. 연동 전에 가맹점 서버 보안 점검을 확인하세요.

주요 연동 문서입니다.

  • 카드 비인증 결제 — 카드번호를 직접 입력받는 key-in 결제
  • 카드 빌링 결제 — 발급된 빌링키로 결제
  • 취소·부분취소 — 승인된 거래의 전체 또는 부분 취소
  • 가상계좌 발급·변경
  • 거래조회

#기타

별도 URL 호출 또는 라이브러리를 통해 제공되는 서비스입니다.

거래영수증 출력, 에스크로, 거래대사, 정산대사 등이 여기에 해당합니다. XPayClient 라이브러리를 사용하지 않고 HTTPS로 직접 호출하는 기능도 있어, 호출 방식이 위 세 가지와 다릅니다.

  • 일자별 거래조회
  • 일자별 정산조회
  • 일자별 현금영수증조회
  • 무이자할부 조회
  • 에스크로

#다음 단계

연동 방식을 정했다면 아래 순서로 진행합니다.

  1. 설치 및 환경 구성 — 언어별 라이브러리를 배치합니다.
  2. conf 설정 — lgdacom.conf와 mall.conf를 설정합니다.
  3. XPayClient 호출 패턴 — 모든 거래가 공유하는 호출 순서입니다.
  4. 선택한 방식의 거래 레퍼런스 문서
