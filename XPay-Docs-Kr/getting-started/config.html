#mall.conf

토스페이먼츠와 통신하는 상점 환경설정 파일입니다. 가맹점 환경에 맞게 수정합니다.

파라미터설명설정값
server_id다수의 mall.conf가 하나의 로그 디렉터리를 바라볼 때, 각 상점 서버에서 발생한 XPayClient 로그를 구분하기 위한 구분자상점 서버별 임의 식별자
timeoutXPayClient 요청 시 Timeout 시간. 설정된 시간을 초과하면 Timeout이 발생합니다.초 단위 정수
log_dirXPayClient 로그를 저장할 디렉터리Full Path
log_level로그를 남기는 기준. DEBUG는 모든 로그를 표시하고, 그 외 레벨은 심각한 에러만 표시합니다.3: INFO, 4: DEBUG
verify_certSSL 인증 유효성 체크. 상점 서버에서 토스페이먼츠 인증서 오류가 발생하면 0으로 설정합니다.0: 검증하지 않음, 1: 검증
verify_hostSSL 인증서 내 domain name 유효성 체크0: 확인하지 않음(테스트 전용), 1: 확인
report_error에러 발생 시 토스페이먼츠 리포트 전송 여부0: 전송하지 않음, 1: 전송
auto_rollback결제 요청 후 timeout 시간을 초과할 때 롤백 수행 여부0: 사용 안 함, 1: 사용
output_UTF8승인결과 전문의 charset. 샘플은 1을 사용합니다. Java 4.1.0.0 은 지정하지 않으면 1로 동작합니다.0: EUC-KR, 1: UTF-8
default_secure_protocolsTLS 1.2 통신을 위한 설정PHP・ASP・JSP: 2048, .NET: 3072
keystore_cacerts_dirJava 전용. 서버 인증서를 검증할 신뢰 저장소(cacerts) 경로. 비워 두면 JDK 기본 cacerts를 사용합니다(권장). 지정한 경로에 파일이 없으면 응답코드 20101로 실패합니다.Full Path 또는 비워 둠
tx_versionJava 전용. 사용할 HttpClient 버전. JDK 1.8 ~ 17 빌드에서만 적용되며, JDK 1.7 빌드는 값과 관계없이 3.x 를 사용합니다.4: HttpClient 4.x, 없거나 그 외: HttpClient 3.x

#상점 ID(MID)와 mertkey 설정

mall.conf 최하단에는 결제 페이지에 설정한 상점 MID(CST_MID)와 이에 대응하는 mertkey가 반드시 설정되어야 합니다.

두 개 이상의 서비스용 MID를 사용하는 경우, 하나의 mall.conf 파일에 모든 MID와 mertkey를 설정할 수 있습니다.

#MID 규칙

서비스용 MID 앞에 소문자 t를 붙이면 테스트용 MID로 적용됩니다.

구분MID설명
서비스용test1234실제 결제에 사용합니다.
테스트용ttest1234서비스용 MID 앞에 t를 붙인 값입니다.
주의 서비스용 MID의 mertkey와 테스트용 MID의 mertkey는 서로 다릅니다. 같은 값으로 설정하지 않도록 주의합니다.

#mertkey 확인

mertkey는 토스페이먼츠 개발자센터에서 확인합니다.

  1. 개발자센터에 로그인합니다.
  2. 개발자센터 > API 키 확인 > mertkey 확인 메뉴로 이동합니다.
  3. 사용할 MID에 해당하는 mertkey 값을 확인합니다.

테스트용과 서비스용이 각각 구분되어 제공됩니다.

#설정 예시

MID = mertkey 형식으로 입력합니다. 라인 첫 글자를 ;(세미콜론)으로 시작하면 설정 파일 로딩 시 주석으로 인식됩니다.

서비스용과 테스트용 동시 설정

ini
; 서비스용 MID
test1234 = test1234의 운영용 mertkey

; 테스트용 MID
ttest1234 = test1234의 테스트용 mertkey

복수 MID 설정

ini
; 첫 번째 상점
test1234 = test1234의 운영용 mertkey
ttest1234 = test1234의 테스트용 mertkey

; 두 번째 상점
test5678 = test5678의 운영용 mertkey
ttest5678 = test5678의 테스트용 mertkey

#conf 파일과 log 파일 보안 정책

mall.conf의 log_dir은 XPay 결제모듈의 승인 요청·승인 결과에서 송수신되는 결제 관련 로그 데이터가 저장되는 경로입니다. 또한 mall.conf에는 실제 결제와 결제 취소에 사용되는 운영용 상점 MID와 mertkey가 저장됩니다.

주의 log_dir과 mall.conf는 절대로 웹에서 접근되는 위치에 지정해서는 안 됩니다. 반드시 외부에서 접근이 불가한 위치로 지정합니다.

#웹 접근이 가능한 경로

아래 경로는 웹에서 접근이 가능하므로 설정 파일과 로그 디렉터리 위치로 사용하지 않습니다.

개발 환경웹 접근 가능 경로
PHP + ApacheDOCUMENT_ROOT 이하
JavaContext Root
ASP, ASP.NET + IISwwwroot 등
참고 만일 웹 접근 가능 경로 이외의 경로에 대한 접근권한이 없는 경우 (ex: 호스팅사 공용서버를 이용), XPayClient 가 아닌 API 방식의 토스페이먼츠 결제서비스를 이용해주시기 바랍니다.

#트러블슈팅

결제 연동 시 자주 발생하는 설정 파일 오류 메시지입니다.

오류 코드원인
10001~/lgdacom까지 설정하는 사용자 디렉터리 설정을 읽지 못하거나 설정되어 있지 않음
10002mall.conf 파일을 찾을 수 없음
10003lgdacom.conf 파일을 찾을 수 없음
20101메시지가 SSL setup failed; keystore_cacerts_dir [...] does not exist이면 keystore_cacerts_dir에 지정한 파일이 없음. 경로를 바로잡거나 비워 둠 (Java)
