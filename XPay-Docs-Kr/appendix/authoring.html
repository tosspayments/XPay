#문서 작성 가이드

HTML을 다뤄보셨다면 마크다운은 금방 익숙해집니다. 이 문서에서 쓰는 문법은 아래 7가지가 전부입니다.

#1. HTML 과 비교

용도마크다운HTML
제목## 요청 파라미터<h2>요청 파라미터</h2>
굵게**필수**<strong>필수</strong>
기울임*참고*<em>참고</em>
코드`LGD_TID`<code>LGD_TID</code>
링크[코드표](../common/codes.md)<a href="…">코드표</a>
목록- 항목<ul><li>항목</li></ul>
줄바꿈빈 줄 하나<p>…</p>

제목은 # 개수가 단계입니다. # 은 문서 제목이라 파일 맨 첫 줄에 하나만 씁니다. 본문 구분은 ##, 그 하위는 ### 을 씁니다.

#2. 표

이 문서에서 가장 많이 쓰는 문법입니다.

markdown
| 파라미터 | 필수 | 최대길이 | 설명 |
| --- | --- | --- | --- |
| `LGD_MID` | 필수 | 15 | 상점아이디입니다. |
| `LGD_OID` | 필수 | 64 | 주문번호입니다. |

규칙 세 가지만 지키면 됩니다.

  1. 둘째 줄 | --- | 은 반드시 있어야 하고, 칸 수가 헤더와 같아야 합니다.
  2. 모든 행의 파이프(|) 개수가 같아야 합니다.
  3. 설명 안에 | 를 쓰려면 \| 로 씁니다.

칸이 세로로 안 맞아도 화면에는 정상 출력됩니다. 보기 좋게 정렬하는 건 선택입니다.

#필수 열은 자동으로 배지가 됩니다

필수 열에 아래 네 값 중 하나를 쓰면 색상 배지로 표시됩니다.

입력값화면
필수빨강
조건부 필수주황
선택회색
미정연회색

#파라미터명은 백틱으로 감싸주세요

`LGD_TID` 처럼 백틱으로 감싸면 파란 배경으로 강조되고, 검색 색인에도 등록됩니다. 감싸지 않으면 검색으로 찾을 수 없습니다.

#3. 코드 예제

백틱 세 개로 감싸고 언어를 적습니다. 복사 버튼이 자동으로 붙습니다.

markdown
```java
XPayClient xpay = new XPayClient();
xpay.Init(configPath, CST_PLATFORM);
```

언어 자리에 쓸 값은 java, php, csharp, html, javascript, bash, text 입니다. JSP는 java, ASP.NET은 csharp 로 씁니다.

#4. 안내 블록

> 로 시작하면 파란 안내 상자가 됩니다. 주의사항이나 전제조건에 씁니다.

markdown
> 상점키는 서버에서만 사용하세요. 클라이언트에 노출되면 안 됩니다.

여러 줄로 쓰려면 각 줄 앞에 > 를 붙입니다.

#6. HTML 직접 쓰기

익숙한 방식이 편하면 HTML 을 그대로 써도 됩니다. 줄 맨 앞이 여는 태그로 시작하면 빈 줄까지 그대로 출력됩니다.

markdown
<details>
<summary>접었다 펼치는 블록</summary>
<p>긴 부가 설명을 접어둘 때 씁니다.</p>
</details>

<div class="note">
  <strong>주의</strong> 직접 만든 안내 블록입니다.
</div>

빈 줄로 끊고 나면 다시 마크다운으로 돌아옵니다.

쓸 수 있는 CSS 클래스는 note(파란 안내 상자), badge req·badge opt(배지), table-wrap(표 감싸기) 입니다. assets/style.css 에서 확인할 수 있습니다.

표는 되도록 마크다운으로 쓰세요. HTML 로 쓰면 필수 배지 자동 변환이 적용되지 않습니다.

#7. 새 페이지 추가

두 단계입니다. 둘째를 빼먹으면 왼쪽 목차에 나오지 않습니다.

하나. docs/ 안에 .md 파일을 만듭니다. 기존 페이지를 복사해서 고치는 것이 가장 빠릅니다.

둘. docs/SUMMARY.md 에 줄을 추가합니다.

markdown
## 거래 레퍼런스

* 카드 API 결제
  * [카드 비인증 결제](reference/card-keyin.md)
  * [새로 추가한 문서](reference/new-page.md)

들여쓰기 두 칸이 하위 항목입니다.

주의 페이지 하단에 원본 문서명이나 "자동 생성 문서이며 필수 여부는 검증이 필요합니다" 같은 안내 문구를 넣지 않습니다. 기존 페이지를 복사해서 만들 때도 이런 문구가 남아 있지 않은지 확인합니다.

#편집 환경 권장

VS Code + Markdown All in One 확장을 권합니다.

  • 표 안에서 Tab 을 누르면 칸이 자동 정렬됩니다. 파이프 개수 맞추는 수고가 없어집니다.
  • Ctrl+Shift+V 로 미리보기가 열립니다.
  • 여러 파일에서 LGD_BUYER 같은 값을 한 번에 찾아 바꿀 수 있습니다. QA 리포트의 불일치 항목을 처리할 때 요긴합니다.

파일은 반드시 UTF-8 로 저장하세요. 메모장을 쓰신다면 다른 이름으로 저장할 때 인코딩을 UTF-8 로 지정해야 합니다. ANSI 로 저장하면 한글이 깨집니다.

#작업 흐름

text
docs/*.md 수정
   → 브라우저 새로고침 (http://localhost/xpay-viewer/)
   → 확인

PHP 모드로 띄워두면 저장하고 새로고침만 하면 됩니다. 빌드 과정이 없습니다.

정적 HTML(static/)로 보고 계시면 수정 후 다시 구워야 합니다.

text
php build-static.php

이미지도 이때 함께 복사됩니다.
