#일자별 정산조회

HTTPS 직접 호출 · servicecode ADJ

지정한 매출일의 정산 내역을 내려받습니다. 지급 예정 금액을 요약한 헤더 라인과 거래 건별 정산 내역인 데이터 라인으로 구성됩니다.

이 기능은 XPayClient 라이브러리를 사용하지 않고 HTTPS로 직접 호출합니다. 호출 방식이 다르므로 XPayClient 호출 패턴은 적용되지 않습니다.

#조회 방식

방식내용
HTTPS 실시간 조회상점 서버가 조회 URL을 호출해 원하는 매출일의 정산 내역을 받습니다. 이 페이지에서 설명합니다.
FTP 파일 수신상점이 FTP 서버를 준비하면 토스페이먼츠가 매출일 다음 날 정산 파일을 올려 줍니다. 별도 협의가 필요합니다. FTP 파일 수신 방식 참고

#요청

text
GET https://pgweb.tosspayments.com/pg/wmp/outerpage/trxdown.jsp?mertid={상점아이디}&servicecode=ADJ&trxdate={yyyyMMdd}&key={key}
파라미터필수설명
mertid필수상점아이디. 소속 상점의 전체 내역을 조회합니다.
servicecode필수ADJ로 고정
trxdate필수조회할 매출일(yyyyMMdd). 전일 매출분까지만 조회할 수 있습니다. 지급일 기준 조회는 협의로 바꿀 수 있습니다.
key필수상점아이디와 mertkey를 이어 붙인 문자열의 MD5 값. key 생성 참고

#key 생성

text
key = MD5( 상점아이디 + mertkey )

mertkey는 mertkey 확인에서 조회합니다. key는 mertkey로 만들기 때문에 조회는 반드시 상점 서버에서 호출하고, 브라우저나 앱에 key를 노출하지 않습니다.

#curl 예제

매출일 2026년 9월 14일의 정산 내역을 내려받아 파일로 저장하는 예제입니다.

bash
MID="상점아이디"
MERTKEY="상점 mertkey"
TRXDATE="20260914"     # 매출일. 전일 매출분까지만 조회할 수 있습니다.

# key = MD5(상점아이디 + mertkey). macOS는 md5sum 대신 `md5 -q -s "${MID}${MERTKEY}"`를 사용합니다.
KEY=$(printf '%s%s' "$MID" "$MERTKEY" | md5sum | awk '{print $1}')

curl -sS -G "https://pgweb.tosspayments.com/pg/wmp/outerpage/trxdown.jsp" \
  --data-urlencode "mertid=${MID}" \
  --data-urlencode "servicecode=ADJ" \
  --data-urlencode "trxdate=${TRXDATE}" \
  --data-urlencode "key=${KEY}" \
  -o "${MID}_ADJ_${TRXDATE}.dat"

#응답 형식

응답은 헤더 라인(H로 시작)과 데이터 라인(D로 시작)으로 구성되며, 필드는 세미콜론(;)으로 구분합니다. 일반적으로 헤더 라인 한 줄과 데이터 라인 여러 줄이 내려옵니다. 구분자는 협의로 바꿀 수 있습니다.

#헤더 라인 (H)

지급될 금액과 건수를 요약한 정보입니다. 11개 필드로 구성됩니다.

순서필드설명
1구분헤더를 나타내는 H
2상점아이디상점아이디
3매출일자매출일자(yyyyMMdd)
4지급예정일자매출일자에 계약된 지급 주기를 더한 날짜(yyyyMMdd)
5거래건수 합계정상 거래(신용카드 매입, 계좌이체 등) + 취소 거래(신용카드 매입취소, 계좌이체 환불 등) + 반송(신용카드) + 취소반송(신용카드) 건수
6거래금액 합계정상 금액 − 취소 금액 − 반송 금액 + 취소반송 금액
7토스페이먼츠 수수료거래금액에 수수료율 등을 적용한 금액. VAT 별도
8VAT토스페이먼츠 수수료의 10%
9당기 발생액거래금액 − (토스페이먼츠 수수료 + VAT). 정산금액과 같습니다.
10지급금액일반적으로 당기 발생액과 같습니다. 미지급 금액이나 기타 사유가 있으면 다를 수 있습니다.
11미지급액정산금액 − 지급금액

#데이터 라인 (D)

헤더의 요약 금액을 구성하는 거래 건별 내역입니다. 11개 필드로 구성됩니다.

순서필드설명
1구분데이터를 나타내는 D
2일련번호데이터 라인 순번
3상점아이디상점아이디
4주문번호상점이 보낸 주문번호
5주문일자상점이 결제를 요청한 날짜(yyyyMMdd)
6결제수단SC0010: 신용카드, SC0030: 계좌이체, SC0040: 무통장입금, SC0060: 휴대폰, SC0070: 유선전화결제, SC0111: 문화상품권, SC0112: 게임상품권
7거래유형결제수단별로 정산에 적용된 거래유형 코드. 거래유형 코드 참고
8거래금액거래유형에 따라 정산에 집계되는 금액
9수수료 계해당 건에 대해 토스페이먼츠가 계산한 수수료 합계(토스페이먼츠 수수료 + VAT)
10매출일자정산 시 정해진 매출일자(yyyyMMdd)
11지급일자정산 시 정해진 지급일자(yyyyMMdd)

#확인 포인트

  • 건별 당기 발생액은 거래금액 − 수수료 계입니다. 결과가 양수면 지급 건, 음수면 차감 건입니다.
  • 에스크로 서비스를 함께 사용하면 같은 매출일자 응답 안에 헤더 라인이 여러 줄 나올 수 있습니다. 건별 지급일은 헤더가 아니라 데이터 라인의 지급일자로 확인합니다.
  • 지급금액과 당기 발생액이 다르면 미지급액 필드를 확인합니다.
  • 조회할 수 있는 날짜는 전일 매출분까지입니다. 당일 매출분은 다음 날 조회합니다.

#FTP 파일 수신 방식

FTP 서버를 공개할 수 있는 상점은 HTTPS로 조회하는 대신 파일로 받을 수 있습니다. 토스페이먼츠와 별도 협의가 필요합니다.

항목내용
생성 주기매출일 다음 날 오전 7시에 매출일자 기준 파일을 한 번 전송합니다.
파일명상점아이디정산일자.dat. 예: tossmid20260914.dat
파일 형식응답 형식과 같습니다.
저장 위치상점이 지정한 경로. 지정하지 않으면 FTP 계정의 홈 디렉터리

상점은 FTP 서버 정보(IP, 계정, 비밀번호, 경로)를 토스페이먼츠에 전달하고, 아래 출발지(토스페이먼츠 서버) IP가 모두 접속할 수 있도록 방화벽과 ACL에 등록합니다.

구분출발지 IP
기존203.233.124.39, 203.233.124.203, 203.233.124.58, 203.233.124.69, 203.233.124.70
AWS13.124.18.147, 13.124.108.35, 3.36.173.151, 3.38.81.32
DC1115.92.221.121, 115.92.221.122, 115.92.221.123, 115.92.221.125, 115.92.221.126, 115.92.221.127

21FTP
20FTP-DATA

AWS와 DC1 IP는 방화벽 및 IP 정보의 인바운드 IP 목록과 같습니다.
