#에스크로

HTTPS 직접 호출 · 배송정보 등록 · 배송완료 등록 · 처리결과 수신

에스크로(결제대금예치제도)는 구매자가 상품을 받을 때까지 결제대금을 제3자에게 맡겨 두는 제도입니다. 토스페이먼츠는 계좌이체와 가상계좌에 에스크로를 제공합니다. 에스크로 결제의 대금을 정산받으려면 상점은 반드시 배송정보 등록 또는 배송완료 등록을 해야 합니다.

이 기능은 XPayClient 라이브러리를 사용하지 않고 HTTPS로 직접 호출합니다. 호출 방식이 다르므로 XPayClient 호출 패턴은 적용되지 않습니다.

#에스크로 흐름

각 단계는 API, 구매자에게 발송되는 이메일, 상점관리자에서 처리할 수 있습니다. 이 페이지는 API로 하는 배송정보 등록·배송완료 등록과, 구매확정·구매취소요청 등의 처리결과 수신을 설명합니다.

#등록 방식 선택

방식dlvtype사용하는 경우이후 처리
배송정보 등록03택배사 코드에 있는 택배사로 발송한 경우운송장번호로 배송을 자동 추적하고, 배송이 끝나면 자동으로 배송완료 처리됩니다.
배송완료 등록01택배사 코드나 운송장번호가 없는 방법으로 전달한 경우(퀵서비스, 자체 배송, 구매자 직접 수령 등)택배사·운송장 정보 대신 실제 수령 정보를 등록합니다.

#요청

두 방식 모두 같은 URL로 파라미터를 보냅니다. 샘플은 application/x-www-form-urlencoded 형식의 POST로 호출합니다.

환경URL
서비스https://pgweb.tosspayments.com/pg/wmp/mertadmin/jsp/escrow/rcvdlvinfo.jsp
테스트https://pgweb.tosspayments.com:9091/pg/wmp/testadmin/jsp/escrow/rcvdlvinfo.jsp

#배송정보 등록 파라미터

파라미터필수최대길이설명
mid필수15상점아이디
oid필수64주문번호
dlvtype필수2등록 구분. 배송정보 등록은 03
dlvdate필수12발송일시(yyyyMMddHHmm). 예: 202609141525는 2026년 9월 14일 오후 3시 25분
dlvcompcode필수2택배사 코드. 택배사 코드 참고
dlvno필수-운송장번호
dlvworker선택-배송자 성명
dlvworkertel선택-배송자 연락처
hashdata필수-위변조 방지용 인증키. hashdata 생성 참고
productid선택-결제 때 보낸 에스크로 상품번호. 상품이 1개이거나 여러 상품을 같은 배송정보로 한 번에 등록하면 생략할 수 있습니다.

#배송완료 등록 파라미터

파라미터필수최대길이설명
mid필수15상점아이디
oid필수64주문번호
dlvtype필수2등록 구분. 배송완료 등록은 01
rcvdate필수12실제 수령일시(yyyyMMddHHmm)
rcvname필수-실제 수령인 이름
rcvrelation필수-수령인과 실제 수령인의 관계
hashdata필수-위변조 방지용 인증키. hashdata 생성 참고
productid선택-결제 때 보낸 에스크로 상품번호. 상품이 1개이거나 여러 상품을 같은 수령정보로 한 번에 등록하면 생략할 수 있습니다.

#hashdata 생성

아래 값을 순서대로 이어 붙인 문자열의 MD5 값(16진수 소문자 32자)입니다. 두 방식의 조합이 다르므로 주의합니다.

text
배송정보 등록(03): MD5( mid + oid + dlvdate + dlvcompcode + dlvno + mertkey )
배송완료 등록(01): MD5( mid + oid + dlvtype + rcvdate + mertkey )

배송정보 등록에는 dlvtype이 들어가지 않고, 배송완료 등록에는 dlvtype(01)이 들어갑니다. mertkey는 mertkey 확인에서 조회하며, 호출은 반드시 상점 서버에서 합니다.

#curl 예제 (배송정보 등록)

CJ대한통운으로 발송한 주문의 배송정보를 테스트 환경에 등록하는 예제입니다.

bash
# 테스트. 서비스는 https://pgweb.tosspayments.com/pg/wmp/mertadmin/jsp/escrow/rcvdlvinfo.jsp
SERVICE_URL="https://pgweb.tosspayments.com:9091/pg/wmp/testadmin/jsp/escrow/rcvdlvinfo.jsp"

MID="상점아이디"
MERTKEY="상점 mertkey"
OID="주문번호"
DLVDATE="202609141525"     # 발송일시 yyyyMMddHHmm
DLVCOMPCODE="CJ"           # 택배사 코드(CJ대한통운)
DLVNO="123456789012"       # 운송장번호

# hashdata = MD5(mid + oid + dlvdate + dlvcompcode + dlvno + mertkey). macOS는 `md5 -q -s "..."`를 사용합니다.
HASHDATA=$(printf '%s' "${MID}${OID}${DLVDATE}${DLVCOMPCODE}${DLVNO}${MERTKEY}" | md5sum | awk '{print $1}')

curl -sS -X POST "$SERVICE_URL" \
  --data-urlencode "mid=${MID}" \
  --data-urlencode "oid=${OID}" \
  --data-urlencode "dlvtype=03" \
  --data-urlencode "dlvdate=${DLVDATE}" \
  --data-urlencode "dlvcompcode=${DLVCOMPCODE}" \
  --data-urlencode "dlvno=${DLVNO}" \
  --data-urlencode "hashdata=${HASHDATA}"

# 응답: 성공하면 OK, 실패하면 FAIL : 실패메시지

#응답

결과응답 본문
성공OK
실패FAIL : 실패메시지

응답 본문의 앞뒤 공백을 제거한 값이 OK일 때만 성공으로 처리합니다.

#처리결과 수신

구매자가 이메일에서 진행한 수령확인·구매취소요청과, 배송정보 등록 후 택배사 배송완료 결과를 상점 페이지로 받아 상점 시스템에 반영할 수 있습니다.

#수신 URL 등록

받을 결과의 종류와 수신 URL을 techsupport@tosspayments.com으로 알려주면 토스페이먼츠가 등록합니다. URL은 하나만 설정할 수 있으며, 모든 결과가 등록된 URL로 전송됩니다.

결과txtype전송 시점
수령확인결과C배송완료 후 구매자가 이메일에서 수령을 확인했을 때
구매취소요청R배송완료 후 구매자가 이메일에서 구매취소를 요청했을 때
택배사 배송완료S배송정보 등록 후 택배사 배송정보에서 배송완료가 확인됐을 때
N/C 처리완료NNegative Confirm 처리가 끝났을 때

#전송 파라미터

파라미터최대길이설명
mid15상점아이디
oid64주문번호
tid24토스페이먼츠 거래번호
txtype1결과 구분. 수신 URL 등록의 표 참고
productid-상품 ID. 기본값 1(향후 사용 예정)
ssn13작업자 주민번호. 개인정보보호법에 따라 .으로 전송됩니다.
ip15작업자 PC의 IP 주소. 개인정보보호법에 따라 .으로 전송됩니다.
mac-작업자 PC의 MAC 주소. 개인정보보호법에 따라 .으로 전송됩니다.
resdate14처리일시(yyyyMMddHHmmss)
hashdata-위변조 검증용 인증키

#hashdata 검증

전달받은 값을 아래 순서로 이어 붙인 문자열의 MD5 값을 만들어 hashdata와 비교합니다. ssn, ip, mac은 전달받은 값(.)을 그대로 사용합니다.

text
MD5( mid + oid + tid + txtype + productid + ssn + ip + mac + resdate + mertkey )
java
String src = mid + oid + tid + txtype + productid + ssn + ip + mac + resdate + mertkey;
byte[] digest = java.security.MessageDigest.getInstance("MD5").digest(src.getBytes());

StringBuilder hash = new StringBuilder();
for (byte b : digest) {
    hash.append(String.format("%02x", b & 0xff));
}

if (hash.toString().equals(hashdata)) {
    // 검증 성공: 결과를 상점 시스템에 반영한 뒤 "OK" 출력
} else {
    // 검증 실패: 로그를 남기고 원인을 확인한 뒤 "OK" 이외의 값 출력
}

#응답과 재전송

결과를 정상적으로 반영했으면 OK만 응답합니다. 토스페이먼츠가 결과를 정상 수신하지 못하면 30분 간격으로 최대 10번까지 다시 보냅니다.

주의 상점이 결과를 정상 처리했더라도 응답이 토스페이먼츠에 닿지 않으면 같은 결과가 다시 전송될 수 있습니다. oid, tid, txtype으로 이미 반영한 결과인지 확인하고 중복 반영하지 않도록 처리합니다.

#확인 포인트

  • 에스크로 결제는 배송정보 등록이나 배송완료 등록을 하지 않으면 정산되지 않습니다.
  • 등록 API의 성공 여부는 응답 본문이 정확히 OK인지로 판단합니다.
  • 처리결과 수신 페이지에는 HTML 태그나 스크립트를 출력하지 않습니다. 응답에 다른 내용이 섞이면 정상 동작을 보장할 수 없습니다.
