#분할정산 (옵션)

LGD_TXNAME 미사용 · LGD_DIVIDE_INFO

하나의 결제 금액을 여러 하위 상점(sub-merchant)으로 나누어 정산하는 옵션입니다. 독립된 거래가 아니라, 결제창 호출이나 API 결제 요청에 분할정산 파라미터를 추가해서 사용합니다.

#적용 가능한 결제 방식

분할정산은 아래 4가지 결제 방식에만 적용할 수 있습니다.

결제 방식비고
신용카드간편결제 포함
계좌이체
가상계좌
빌링 승인카드 빌링 결제

#결제 요청

결제창을 열거나 API로 결제를 요청할 때 아래 파라미터를 함께 보냅니다.

파라미터필수설명
LGD_DIVIDE_INFO필수하위 상점별 정산 정보(JSON). LGD_DIVIDE_INFO 구성 참고
LGD_PRODUCTINFO필수분할정산 상점은 padj로 고정합니다. 하위 상점별 상품명은 LGD_DIVIDE_INFO의 productinfo에 넣습니다.

결제 요청 해쉬(LGD_HASHDATA)는 일반 결제와 같습니다. 분할정산 정보는 해쉬에 넣지 않습니다. 자세한 내용은 요청 해쉬를 참고합니다.

#LGD_DIVIDE_INFO 구성

정산할 하위 상점마다 JSON 객체를 하나씩 만듭니다.

항목설명
sub_merchantid정산할 하위 상점아이디
amount해당 하위 상점으로 정산할 상품 금액
productinfo해당 하위 상점으로 정산할 상품명
netamount해당 금액 중 과세금액
vat해당 금액 중 부가세
taxfreeamount해당 금액 중 면세금액

먼저 하위 상점별로 JSON 객체를 만듭니다.

text
{"sub_merchantid":"MID1","amount":"2000","productinfo":"상품1"}

다음으로 객체들을 배열로 묶고, 배열 이름을 divideinfo로 지정합니다.

text
{"divideinfo":[
  {"sub_merchantid":"MID1","amount":"2000","productinfo":"상품1"},
  {"sub_merchantid":"MID2","amount":"3000","productinfo":"상품2"},
  {"sub_merchantid":"MID3","amount":"4000","productinfo":"상품3"}
]}

마지막으로 JSON의 큰따옴표(")를 &quot;로 바꾼 값을 LGD_DIVIDE_INFO에 넣습니다.

text
{&quot;divideinfo&quot;:[{&quot;sub_merchantid&quot;:&quot;MID1&quot;,&quot;amount&quot;:&quot;2000&quot;,&quot;productinfo&quot;:&quot;상품1&quot;},{&quot;sub_merchantid&quot;:&quot;MID2&quot;,&quot;amount&quot;:&quot;3000&quot;,&quot;productinfo&quot;:&quot;상품2&quot;},{&quot;sub_merchantid&quot;:&quot;MID3&quot;,&quot;amount&quot;:&quot;4000&quot;,&quot;productinfo&quot;:&quot;상품3&quot;}]}

#코드 예제 (결제창 호출)

토스페이먼츠가 제공하는 JSP 샘플 payreq_crossplatform.jsp에서 분할정산에 필요한 부분만 추린 코드입니다. 나머지 결제창 호출 코드는 통합결제창 결제와 같습니다.

java
<%
// 분할정산 상점은 반드시 padj로 설정합니다. (수정 불가)
String LGD_PRODUCTINFO = "padj";

// 하위 상점별 정산 정보
String LGD_DIVIDE_INFO = "{\"divideinfo\":["
    + "{\"sub_merchantid\":\"하위상점아이디1\",\"amount\":\"2000\",\"productinfo\":\"상품1\"},"
    + "{\"sub_merchantid\":\"하위상점아이디2\",\"amount\":\"3000\",\"productinfo\":\"상품2\"}"
    + "]}";

payReqMap.put("LGD_PRODUCTINFO", LGD_PRODUCTINFO);
payReqMap.put("LGD_DIVIDE_INFO", LGD_DIVIDE_INFO.replace("\"", "&quot;"));
%>

payReqMap의 값은 다른 결제 파라미터와 함께 결제 요청 Form의 hidden 필드로 넣습니다.

#취소

분할정산으로 결제한 건을 취소할 때는 분할정산 파라미터를 함께 보냅니다. 부분취소는 취소 금액이 어느 하위 상점에서 발생했는지도 지정해야 합니다.

파라미터전체취소부분취소설명
LGD_DIVIDE_YN필수필수분할정산 상점 여부. 분할정산 상점은 Y
LGD_DIVIDE_MID_SUB-필수취소 금액이 발생한 하위 상점아이디

취소의 나머지 파라미터는 취소·부분취소를 참고합니다.

#코드 예제 (취소)

토스페이먼츠가 제공하는 JSP 샘플 CancelRefund.jsp에서 분할정산 취소에 필요한 부분만 추린 코드입니다.

java
<%@ page import="lgdacom.XPayClient.XPayClient" %>
<%
String configPath = "C:/lgdacom";  // 웹에서 접근할 수 없는 경로에 둡니다.

XPayClient xpay = new XPayClient();
xpay.Init(configPath, CST_PLATFORM);
xpay.Init_TX(LGD_MID);

xpay.Set("LGD_TXNAME", "Cancel");
xpay.Set("LGD_MID", LGD_MID);
xpay.Set("LGD_TID", LGD_TID);
xpay.Set("LGD_DIVIDE_YN", "Y");    // 분할정산 상점은 반드시 Y

// 가상계좌 환불은 환불계좌 정보가 필수입니다.
xpay.Set("LGD_RFBANKCODE", LGD_RFBANKCODE);
xpay.Set("LGD_RFACCOUNTNUM", LGD_RFACCOUNTNUM);
xpay.Set("LGD_RFCUSTOMERNAME", LGD_RFCUSTOMERNAME);
xpay.Set("LGD_RFPHONE", LGD_RFPHONE);

if (xpay.TX()) {
    // 통신 성공. xpay.m_szResCode, xpay.m_szResMsg로 취소 결과를 확인합니다.
} else {
    // API 요청 실패. xpay.m_szResCode, xpay.m_szResMsg로 사유를 확인합니다.
}
%>

부분취소는 LGD_TXNAME을 PartialCancel로 하고, LGD_DIVIDE_YN과 함께 하위 상점아이디를 보냅니다.

java
xpay.Set("LGD_TXNAME", "PartialCancel");
xpay.Set("LGD_DIVIDE_YN", "Y");
xpay.Set("LGD_DIVIDE_MID_SUB", "하위상점아이디1");  // 취소 금액이 발생한 하위 상점

#확인 포인트

  • 분할정산은 LGD_TXNAME이 따로 없는 옵션입니다. 결제와 취소는 원래 거래의 방식 그대로 요청하고, 분할정산 파라미터만 추가합니다.
  • 분할정산 상점은 LGD_PRODUCTINFO를 padj로 보내고, 실제 상품명은 하위 상점별 productinfo에 넣습니다.
  • 부분취소할 때 LGD_DIVIDE_MID_SUB를 빠뜨리면 어느 하위 상점의 금액을 취소하는지 알 수 없습니다. 하위 상점별로 나눠 부분취소합니다.
