#안심키인 결제창

LGD_TXNAME 미사용 · 승인에 XPayClient 미사용

구매자의 신용카드 정보를 안심키인 결제창에 입력해 결제하는 방식입니다. 표준 결제창과 달리 결제창이 승인까지 처리하므로, 상점은 XPayClient로 승인을 요청하지 않습니다. 결제 결과는 결제창이 LGD_NOTEURL(서버 간 전달)과 LGD_RETURNURL(브라우저 이동)로 보내 줍니다.

참고 이 페이지는 Non-ActiveX 안심키인 결제창을 기준으로 합니다. 결제를 취소할 때는 다른 결제와 같이 취소·부분취소를 사용합니다.

#이용 조건

항목내용
결제 가능 카드비씨, 국민, 현대, 하나, 삼성, 롯데, 신한
국민카드 제한꽃배달, 여행사, 화장품, 호텔, 숙박 예약 업종만 이용할 수 있습니다.
로그인결제창에서 법인 공동인증서(구 공인인증서)로 로그인합니다. 로그인 유지 시간 안에 결제가 이어지면 로그인 상태가 유지됩니다.

#결제 흐름

순서구간내용
1구매자 → 결제 요청 페이지구매자가 상점의 결제 요청 페이지에서 결제를 요청합니다.
2결제 요청 페이지 → 결제창open_paymentwindow()로 안심키인 결제창을 엽니다.
3구매자 → 결제창구매자가 카드 정보를 입력하고 결제합니다. 결제창이 승인을 처리합니다.
4결제창 → LGD_NOTEURL토스페이먼츠가 결제 결과를 상점 서버로 전달합니다(백엔드). 상점은 결과를 DB에 반영합니다.
5LGD_NOTEURL → 토스페이먼츠상점이 DB 처리 결과를 OK 또는 그 외 값으로 응답합니다.

LGD_RETURNURL을 함께 설정하면 결제가 끝난 뒤 결제 결과가 브라우저를 통해 해당 페이지로도 전달됩니다. 자세한 내용은 결제 결과 수신을 참고합니다.

#결제 요청 페이지 작성

#1. Form 구성

결제 요청 파라미터를 id="LGD_PAYINFO" Form에 hidden 필드로 넣습니다.

html
<form method="post" id="LGD_PAYINFO">
  <input type="hidden" name="LGD_MID" value="상점아이디">
  <input type="hidden" name="LGD_OID" value="주문번호">
  <input type="hidden" name="LGD_AMOUNT" value="결제금액">
  <input type="hidden" name="LGD_BUYER" value="구매자명">
  <input type="hidden" name="LGD_PRODUCTINFO" value="상품명">
  <input type="hidden" name="LGD_NOTEURL" value="https://상점URL/note_url.jsp">
  <input type="hidden" name="LGD_ACTIVEXYN" value="N">
  <!-- 결제 완료 후 결과 페이지로 이동하려면 아래 두 필드를 함께 추가합니다. -->
  <input type="hidden" name="LGD_RETURNURL" value="https://상점URL/return_url.jsp">
  <input type="hidden" name="LGD_CUSTOM_RESULTTYPE" value="SUBMIT">
</form>

#2. 결제창 스크립트 포함

안심키인 결제창 스크립트는 반드시 </body> 아래에 넣습니다.

html
</body>
<script language="javascript" src="https://xpay.tosspayments.com/ansim-keyin/js/ansim_crossplatform.js" type="text/javascript"></script>
</html>

#3. 결제창 호출

결제 버튼을 누르면 open_paymentwindow()에 Form과 결제 환경을 넘겨 결제창을 엽니다. 결제 환경은 test(테스트) 또는 service(서비스)입니다.

html
<script type="text/javascript">
function doAnsimKeyin() {
    // CST_PLATFORM: test(테스트) 또는 service(서비스)
    ret = open_paymentwindow(document.getElementById('LGD_PAYINFO'), '<%= CST_PLATFORM %>');
}
</script>

<input type="button" value="결제요청" onclick="doAnsimKeyin()">

테스트 환경에서는 LGD_MID에 발급받은 상점아이디 앞에 t를 붙인 값을 사용합니다. 자세한 내용은 MID 규칙을 참고합니다.

#결제창 호출 요청 파라미터

파라미터필수최대길이설명
LGD_MID필수15토스페이먼츠에서 발급한 상점아이디
LGD_OID필수64상점 주문번호. 상점아이디별로 유일해야 하며 공백과 특수문자는 쓸 수 없습니다(최대 63자). 주문번호 규칙 참고
LGD_AMOUNT필수12결제금액. 쉼표 없이 숫자로만 입력합니다(예: 23400).
LGD_BUYER필수10구매자명
LGD_PRODUCTINFO필수128상품명(구매내역)
LGD_ACTIVEXYN필수1ActiveX 사용 여부. 반드시 N으로 보냅니다. N 이외의 값을 보내거나 파라미터를 생략하면 ActiveX 방식으로 동작합니다.
LGD_NOTEURL선택255결제 결과를 받아 DB에 반영할 상점 페이지 URL. 결제 결과를 DB에 반영하려면 설정합니다. 표준 포트(HTTP 80, HTTPS 443)만 사용할 수 있습니다.
LGD_RETURNURL선택255결제 완료 후 결과를 전달받을 페이지 URL. LGD_CUSTOM_RESULTTYPE과 함께 사용합니다.
LGD_CUSTOM_RESULTTYPE선택-LGD_RETURNURL을 사용할 때 SUBMIT으로 보냅니다. 보내지 않으면 결제가 끝난 뒤에도 결제창이 그대로 남아 있습니다.
LGD_TAXFREEAMOUNT선택9총 결제금액 중 면세금액. 면세상품이 포함된 경우에 사용하며, 사용 전 "부분면세" 계약 여부를 확인해야 합니다.
LGD_ENCODING선택-결제창 인코딩. 기본값은 EUC-KR이며, 그 외 인코딩(예: UTF-8)을 쓸 때만 보냅니다.
LGD_ENCODING_NOTEURL선택-LGD_NOTEURL로 전달하는 결제 결과의 인코딩. 기본값은 EUC-KR이며, UTF-8로 보내면 UTF-8로 인코딩한 값을 전달합니다.

#결제 결과 수신

수신 방법전달 경로용도
LGD_NOTEURL토스페이먼츠 서버 → 상점 서버결제 결과를 검증하고 DB에 반영합니다.
LGD_RETURNURL결제창 → 구매자 브라우저 → 상점 페이지결제 결과 화면을 보여 주고 결제창을 닫습니다.

두 곳 모두 같은 결제 결과 파라미터를 받습니다. 결제 결과는 브라우저를 거치지 않는 LGD_NOTEURL에서 DB에 반영합니다.

#LGD_NOTEURL 처리

LGD_NOTEURL 페이지는 아래 순서로 결과를 처리합니다.

  1. 전달받은 파라미터로 응답 해쉬를 만들어 LGD_HASHDATA와 비교합니다.
  2. 해쉬가 일치하면 LGD_RESPCODE에 따라 결제 성공 또는 실패를 DB에 반영합니다.
  3. DB 처리가 정상이면 OK를 응답합니다.
상황상점 처리응답
해쉬 일치, LGD_RESPCODE가 0000결제 성공을 DB에 반영합니다.반영에 성공하면 OK
해쉬 일치, LGD_RESPCODE가 0000 이외결제 실패를 DB에 반영합니다.반영에 성공하면 OK
해쉬 불일치DB에 반영하지 않고 검증 실패를 로그로 남깁니다.OK 이외의 값

응답 해쉬는 아래 순서로 이어 붙인 문자열의 MD5 값입니다. 자세한 내용은 응답 해쉬를 참고합니다.

text
LGD_HASHDATA = MD5( LGD_MID + LGD_OID + LGD_AMOUNT + LGD_RESPCODE + LGD_TIMESTAMP + LGD_MERTKEY )

안심키인은 승인에 XPayClient를 쓰지 않으므로 LGD_NOTEURL 페이지에서 mertkey로 직접 해쉬를 만듭니다. mertkey는 mertkey 확인에서 조회하고, 외부에 노출되지 않는 서버 코드나 설정에 둡니다.

java
String LGD_MERTKEY = "";  // 상점 mertkey

String src = LGD_MID + LGD_OID + LGD_AMOUNT + LGD_RESPCODE + LGD_TIMESTAMP + LGD_MERTKEY;
byte[] digest = java.security.MessageDigest.getInstance("MD5").digest(src.getBytes());

StringBuilder hash = new StringBuilder();
for (byte b : digest) {
    hash.append(String.format("%02x", b & 0xff));
}

if (hash.toString().equals(LGD_HASHDATA)) {
    // 해쉬 검증 성공: LGD_RESPCODE에 따라 DB 처리 후 "OK" 출력
} else {
    // 해쉬 검증 실패: 로그를 남기고 "OK" 이외의 값 출력
}
주의 DB 처리가 정상으로 끝나면 OK만 응답합니다. OK 이외의 문자열이 섞이면 실패로 처리됩니다. 실패로 처리된 결제 결과는 2시간 동안 LGD_NOTEURL로 다시 전송됩니다.

실패로 처리된 건의 사유는 상점관리자의 결제내역조회 > 전체거래내역조회 > 전송실패내역 조회에서 거래를 조회한 뒤, 거래번호(TID)를 눌러 상세 화면에서 확인합니다.

#LGD_RETURNURL 처리 (선택)

LGD_RETURNURL과 LGD_CUSTOM_RESULTTYPE=SUBMIT을 함께 보내면, 결제가 끝난 뒤 결제창이 결제 결과를 LGD_RETURNURL로 전달합니다. 이 페이지에서는 결제 결과를 보여 주고, 필요하면 JavaScript로 결제창을 닫습니다.

LGD_CUSTOM_RESULTTYPE을 보내지 않으면 결제가 끝난 뒤에도 결제창이 그대로 남아 있습니다.

#연동 전 확인 사항

#주문번호(LGD_OID) 규칙

  1. 주문번호는 상점아이디별로 유일해야 합니다. 상점아이디별 주문을 구분하는 값입니다.
  2. 공백과 특수문자(/, :, *, ?, ", <, >, | 등)는 사용할 수 없습니다. 영문, 숫자, _, -로만 구성하는 것을 권장합니다.

#거래번호(LGD_TID) 보관

LGD_TID는 토스페이먼츠가 승인 건마다 부여하는 거래번호입니다. 오류 추적과 취소에 필요하므로 상점 결제 결과 DB에 반드시 보관합니다.

#샘플 파일

JSP 샘플 패키지(TossPayments_NonActive_AnsimKeyin_JSP)는 두 파일로 구성됩니다. 기본 인코딩은 EUC-KR입니다.

파일설명상점 수정
pay_req_na.jsp결제 요청 페이지. Form 구성, 결제창 스크립트 포함, open_paymentwindow() 호출CST_PLATFORM, CST_MID, LGD_NOTEURL 변경
note_url.jsp결제 결과 DB 처리 페이지. 응답 해쉬 검증 후 OK 응답LGD_MERTKEY 입력, DB 처리 구현

#오류 처리

LGD_RESPCODE가 0000이면 성공입니다. 전체 목록은 응답 코드를 참고하세요.
