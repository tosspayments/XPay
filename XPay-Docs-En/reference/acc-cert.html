#Account validity check

LGD_TXNAME AccCert

Checks whether the account holder name matches the account number.

For the call sequence, see XPayClient call pattern.

#Account validity request parameters

LGD_MIDRequired15Merchant ID issued by Toss Payments
LGD_GUBUNTBD1Identity verification type. 2: bank + account number + account holder (holder check). 3: bank + account number + account holder + date of birth (holder and date-of-birth check). 4: bank + account number (account validity check). 5: bank + account number + date of birth (date-of-birth check). 6: bank + account number (account validity check; unlike type 4, returns the account holder name). LGD_BANKCODETBD3Bank code of the deposit account
LGD_ACCOUNTNOTBD-Bank account number
LGD_NAMETBD15Name (account holder name). Required when LGD_GUBUN is 2 or 3.
LGD_PRIVATENOTBD10Buyer's date of birth (6 digits, YYMMDD) or business registration number (10 digits)

#Code example

The following code extracts the parts needed for integration from the JSP sample AccCert.jsp provided by Toss Payments. Samples in other languages follow the same order.

java
<%@ page import="lgdacom.XPayClient.XPayClient" %>
<%
String configPath = "C:/lgdacom";

XPayClient xpay = new XPayClient();
if (!xpay.Init(configPath, CST_PLATFORM)) {
    // Failed to load the configuration files. Check the lgdacom.conf and mall.conf installation.
    return;
}

xpay.Init_TX(LGD_MID);
xpay.Set("LGD_TXNAME", "AccCert");
xpay.Set("LGD_GUBUN", LGD_GUBUN);
xpay.Set("LGD_BANKCODE", LGD_BANKCODE);
xpay.Set("LGD_ACCOUNTNO", LGD_ACCOUNTNO);
xpay.Set("LGD_NAME", LGD_NAME);
xpay.Set("LGD_PRIVATENO", LGD_PRIVATENO);
xpay.Set("LGD_BUYERIP", LGD_BUYERIP);

if (xpay.TX()) {
    if ("0000".equals(xpay.m_szResCode)) {
        String respCode = xpay.Response("LGD_RESPCODE", 0);
        String tid      = xpay.Response("LGD_TID", 0);
        if ("0000".equals(respCode)) {
            // Succeeded. Save the transaction result to the DB.
            boolean isDBOK = true;
            if (!isDBOK) {
                xpay.Rollback("Rollback due to merchant DB processing failure [TID:" + tid + "]");
            }
        }
    }
}
%>

#Key points

  • xpay.m_szResCode is the communication response code, and LGD_RESPCODE is the transaction response code. A payment succeeds only when both are 0000. Communication can succeed while the transaction fails, so always check both values.
  • Get response values with xpay.Response(parameter name, 0). The second argument is the index; use a value other than 0 only when there are multiple responses with the same name.
  • If approval succeeds but saving to the merchant database fails, cancel automatically with xpay.Rollback(). If you skip this, the customer is charged but no order exists.
  • To iterate over the entire response, use xpay.ResponseNameCount() and xpay.ResponseName(i).

Source: sample TossPayments_AccCert_JSP/TossPayments_AccCert_JSP/AccCert.jsp

#Error handling

LGD_RESPCODE is 0000 on success. For the complete list, see Response codes.
