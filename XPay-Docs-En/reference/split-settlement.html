#Split settlement (option)

LGD_TXNAME not used · LGD_DIVIDE_INFO

An option that splits one payment amount for settlement across multiple sub-merchants. It is not a standalone transaction; you add split settlement parameters to a payment window request or an API payment request.

#Supported payment methods

Split settlement applies only to the following four payment methods.

Payment methodNotes
Credit cardIncludes easy payment
Bank transfer
Virtual account
Billing approvalCard billing payment

#Payment request

Send the following parameters when you open the payment window or request payment through the API.

ParameterRequiredDescription
LGD_DIVIDE_INFORequiredSettlement information for each sub-merchant (JSON). See Building LGD_DIVIDE_INFO.
LGD_PRODUCTINFORequiredFixed to padj for split settlement merchants. Put each sub-merchant's product name in productinfo of LGD_DIVIDE_INFO.

The payment request hash (LGD_HASHDATA) is the same as for regular payments. Do not include the split settlement information in the hash. For details, see Request hash.

#Building LGD_DIVIDE_INFO

Create one JSON object for each sub-merchant to settle to.

ItemDescription
sub_merchantidSub-merchant ID to settle to
amountProduct amount to settle to the sub-merchant
productinfoProduct name to settle to the sub-merchant
netamountTaxable amount within the amount
vatVAT within the amount
taxfreeamountTax-free amount within the amount

First, create a JSON object for each sub-merchant.

text
{"sub_merchantid":"MID1","amount":"2000","productinfo":"Product 1"}

Next, group the objects into an array and name the array divideinfo.

text
{"divideinfo":[
  {"sub_merchantid":"MID1","amount":"2000","productinfo":"Product 1"},
  {"sub_merchantid":"MID2","amount":"3000","productinfo":"Product 2"},
  {"sub_merchantid":"MID3","amount":"4000","productinfo":"Product 3"}
]}

Finally, replace the double quotes (") in the JSON with &quot; and put the result in LGD_DIVIDE_INFO.

text
{&quot;divideinfo&quot;:[{&quot;sub_merchantid&quot;:&quot;MID1&quot;,&quot;amount&quot;:&quot;2000&quot;,&quot;productinfo&quot;:&quot;Product 1&quot;},{&quot;sub_merchantid&quot;:&quot;MID2&quot;,&quot;amount&quot;:&quot;3000&quot;,&quot;productinfo&quot;:&quot;Product 2&quot;},{&quot;sub_merchantid&quot;:&quot;MID3&quot;,&quot;amount&quot;:&quot;4000&quot;,&quot;productinfo&quot;:&quot;Product 3&quot;}]}

#Code example (payment window request)

The following code extracts the parts needed for split settlement from the JSP sample payreq_crossplatform.jsp provided by Toss Payments. The rest of the payment window code is the same as in Unified payment window.

java
<%
// Split settlement merchants must set this to padj. (Do not change)
String LGD_PRODUCTINFO = "padj";

// Settlement information for each sub-merchant
String LGD_DIVIDE_INFO = "{\"divideinfo\":["
    + "{\"sub_merchantid\":\"SUB_MERCHANT_ID_1\",\"amount\":\"2000\",\"productinfo\":\"Product 1\"},"
    + "{\"sub_merchantid\":\"SUB_MERCHANT_ID_2\",\"amount\":\"3000\",\"productinfo\":\"Product 2\"}"
    + "]}";

payReqMap.put("LGD_PRODUCTINFO", LGD_PRODUCTINFO);
payReqMap.put("LGD_DIVIDE_INFO", LGD_DIVIDE_INFO.replace("\"", "&quot;"));
%>

Put the values in payReqMap in hidden fields of the payment request form, together with the other payment parameters.

#Cancellation

When you cancel a payment made with split settlement, send the split settlement parameters as well. For partial cancellations, you must also specify which sub-merchant the canceled amount belongs to.

ParameterFull cancellationPartial cancellationDescription
LGD_DIVIDE_YNRequiredRequiredWhether the merchant uses split settlement. Y for split settlement merchants.
LGD_DIVIDE_MID_SUB-RequiredSub-merchant ID where the canceled amount occurred

For the remaining cancellation parameters, see Cancel and partially cancel.

#Code example (cancellation)

The following code extracts the parts needed for split settlement cancellations from the JSP sample CancelRefund.jsp provided by Toss Payments.

java
<%@ page import="lgdacom.XPayClient.XPayClient" %>
<%
String configPath = "C:/lgdacom";  // Place this in a path that is not accessible from the web.

XPayClient xpay = new XPayClient();
xpay.Init(configPath, CST_PLATFORM);
xpay.Init_TX(LGD_MID);

xpay.Set("LGD_TXNAME", "Cancel");
xpay.Set("LGD_MID", LGD_MID);
xpay.Set("LGD_TID", LGD_TID);
xpay.Set("LGD_DIVIDE_YN", "Y");    // Always Y for split settlement merchants

// Refund account information is required for virtual account refunds.
xpay.Set("LGD_RFBANKCODE", LGD_RFBANKCODE);
xpay.Set("LGD_RFACCOUNTNUM", LGD_RFACCOUNTNUM);
xpay.Set("LGD_RFCUSTOMERNAME", LGD_RFCUSTOMERNAME);
xpay.Set("LGD_RFPHONE", LGD_RFPHONE);

if (xpay.TX()) {
    // Communication succeeded. Check the cancellation result with xpay.m_szResCode and xpay.m_szResMsg.
} else {
    // API request failed. Check xpay.m_szResCode and xpay.m_szResMsg for the reason.
}
%>

For a partial cancellation, set LGD_TXNAME to PartialCancel and send the sub-merchant ID together with LGD_DIVIDE_YN.

java
xpay.Set("LGD_TXNAME", "PartialCancel");
xpay.Set("LGD_DIVIDE_YN", "Y");
xpay.Set("LGD_DIVIDE_MID_SUB", "SUB_MERCHANT_ID_1");  // Sub-merchant where the canceled amount occurred

#Key points

  • Split settlement is an option without its own LGD_TXNAME. Request payments and cancellations as you normally would for the original transaction, and add only the split settlement parameters.
  • Split settlement merchants send padj in LGD_PRODUCTINFO and put the actual product names in productinfo for each sub-merchant.
  • If you omit LGD_DIVIDE_MID_SUB in a partial cancellation, there is no way to know which sub-merchant's amount to cancel. Partially cancel separately for each sub-merchant.
