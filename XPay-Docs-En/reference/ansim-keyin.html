#Ansim Key-in payment window

LGD_TXNAME not used · XPayClient not used for approval

The buyer enters credit card information in the Ansim Key-in payment window to pay. Unlike the standard payment window, this window also processes the approval, so the merchant does not request approval through XPayClient. The payment window sends the result to LGD_NOTEURL (server to server) and LGD_RETURNURL (browser redirect).

Note This page is based on the Non-ActiveX Ansim Key-in payment window. To cancel a payment, use Cancel and partially cancel as with other payments.

#Requirements

ItemDescription
Supported cardsBC, KB Kookmin, Hyundai, Hana, Samsung, Lotte, Shinhan
KB Kookmin Card restrictionAvailable only for flower delivery, travel agency, cosmetics, hotel, and accommodation booking businesses.
Sign-inThe buyer signs in to the payment window with a corporate digital certificate (formerly called a public certificate). The session stays signed in as long as payments continue within the session timeout.

#Payment flow

OrderSegmentDescription
1Buyer → payment request pageThe buyer requests payment on the merchant's payment request page.
2Payment request page → payment windowOpens the Ansim Key-in payment window with open_paymentwindow().
3Buyer → payment windowThe buyer enters card information and pays. The payment window processes the approval.
4Payment window → LGD_NOTEURLToss Payments sends the payment result to the merchant server (backend). The merchant records the result in its database.
5LGD_NOTEURL → Toss PaymentsThe merchant responds with OK or another value to report the result of DB processing.

If you also set LGD_RETURNURL, the payment result is also delivered to that page through the browser after payment completes. For details, see Receive payment results.

#Build the payment request page

#1. Build the form

Put the payment request parameters in hidden fields of the form with id="LGD_PAYINFO".

html
<form method="post" id="LGD_PAYINFO">
  <input type="hidden" name="LGD_MID" value="merchant ID">
  <input type="hidden" name="LGD_OID" value="order ID">
  <input type="hidden" name="LGD_AMOUNT" value="payment amount">
  <input type="hidden" name="LGD_BUYER" value="buyer name">
  <input type="hidden" name="LGD_PRODUCTINFO" value="product name">
  <input type="hidden" name="LGD_NOTEURL" value="https://merchant-url/note_url.jsp">
  <input type="hidden" name="LGD_ACTIVEXYN" value="N">
  <!-- To redirect to a result page after payment, add the following two fields. -->
  <input type="hidden" name="LGD_RETURNURL" value="https://merchant-url/return_url.jsp">
  <input type="hidden" name="LGD_CUSTOM_RESULTTYPE" value="SUBMIT">
</form>

#2. Include the payment window script

Always place the Ansim Key-in payment window script after </body>.

html
</body>
<script language="javascript" src="https://xpay.tosspayments.com/ansim-keyin/js/ansim_crossplatform.js" type="text/javascript"></script>
</html>

#3. Open the payment window

When the buyer clicks the payment button, pass the form and the payment environment to open_paymentwindow() to open the payment window. The environment is test or service (production).

html
<script type="text/javascript">
function doAnsimKeyin() {
    // CST_PLATFORM: test or service
    ret = open_paymentwindow(document.getElementById('LGD_PAYINFO'), '<%= CST_PLATFORM %>');
}
</script>

<input type="button" value="Pay" onclick="doAnsimKeyin()">

In the test environment, use the issued merchant ID prefixed with t for LGD_MID. For details, see MID rules.

#Receive payment results

Delivery methodDelivery pathPurpose
LGD_NOTEURLToss Payments server → merchant serverVerifies the payment result and updates the database.
LGD_RETURNURLPayment window → buyer's browser → merchant pageShows the payment result page and closes the payment window.

Both receive the same payment result parameters. Record payment results in your database from LGD_NOTEURL, which does not go through the browser.

#Handle LGD_NOTEURL

The LGD_NOTEURL page processes the result in the following order.

  1. Create the response hash from the received parameters and compare it with LGD_HASHDATA.
  2. If the hash matches, record the payment success or failure in the database according to LGD_RESPCODE.
  3. If DB processing succeeds, respond with OK.
SituationMerchant actionResponse
Hash matches, LGD_RESPCODE is 0000Records the successful payment in the database.OK if the update succeeds
Hash matches, LGD_RESPCODE is not 0000Records the failed payment in the database.OK if the update succeeds
Hash mismatchDo not update the database. Log the verification failure.A value other than OK

The response hash is the MD5 value of the following values concatenated in order. For details, see Response hash.

text
LGD_HASHDATA = MD5( LGD_MID + LGD_OID + LGD_AMOUNT + LGD_RESPCODE + LGD_TIMESTAMP + LGD_MERTKEY )

Because Ansim Key-in does not use XPayClient for approval, the LGD_NOTEURL page creates the hash directly with the mertkey. Look up the mertkey in Find your mertkey, and keep it in server code or configuration that is not exposed externally.

java
String LGD_MERTKEY = "";  // Merchant mertkey

String src = LGD_MID + LGD_OID + LGD_AMOUNT + LGD_RESPCODE + LGD_TIMESTAMP + LGD_MERTKEY;
byte[] digest = java.security.MessageDigest.getInstance("MD5").digest(src.getBytes());

StringBuilder hash = new StringBuilder();
for (byte b : digest) {
    hash.append(String.format("%02x", b & 0xff));
}

if (hash.toString().equals(LGD_HASHDATA)) {
    // Hash verified: process the DB according to LGD_RESPCODE, then output "OK"
} else {
    // Hash verification failed: log it and output a value other than "OK"
}
Caution When DB processing completes successfully, respond with OK only. If the response contains anything other than OK, it is treated as a failure. Payment results treated as failed are resent to LGD_NOTEURL for 2 hours.

To find the reason for a failed delivery, look up the transaction in the merchant admin under Payment history > All transactions > Failed deliveries, and then click the transaction ID (TID) to open the details.

#Handle LGD_RETURNURL (optional)

If you send LGD_RETURNURL together with LGD_CUSTOM_RESULTTYPE=SUBMIT, the payment window delivers the result to LGD_RETURNURL after payment completes. On this page, show the payment result and close the payment window with JavaScript if needed.

If you do not send LGD_CUSTOM_RESULTTYPE, the payment window stays open after payment completes.

#Before you integrate

#Order ID (LGD_OID) rules

  1. The order ID must be unique per merchant ID. It identifies orders for each merchant ID.
  2. Spaces and special characters (such as /, :, *, ?, ", <, >, and |) are not allowed. We recommend using only letters, digits, _, and -.

#Store the transaction ID (LGD_TID)

LGD_TID is the transaction ID that Toss Payments assigns to each approval. It is required for troubleshooting and cancellations, so always store it in your payment result database.
