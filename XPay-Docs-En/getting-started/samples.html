#Sample file structure

The XPay sample packages provided by Toss Payments consist of the libraries required for integration, configuration files, and sample pages that implement the payment flow. The file structure differs by development language. For library installation, see Installation and environment; for the configuration files, see Configure conf files.

Note The default encoding of the sample pages is EUC-KR. The samples contain only the basics, so modify them to fit your environment.

#Sample page flow

The payment sample pages work in the following order. For code in each language, see XPayClient call pattern.

OrderPageRole
1sample_crossplatformEnters the information required for the payment request.
2payreq_crossplatformOpens the XPay authentication payment window with the entered information.
3Authentication payment windowThe buyer selects a payment method and enters additional information.
4returnurlAfter authentication, receives LGD_PAYKEY (authentication key) and passes it to the payment_return function of the parent page, payreq_crossplatform.
5payresRequests final payment with LGD_PAYKEY and processes the result.

#Common sample pages

The sample pages differ only in their file extension by language (.jsp, .php, .asp, .aspx); their roles are the same. All of them require development to fit your environment.

FileDescriptionWork type
sample_crossplatform.htmlData entry page for paymentDevelopment required
payreq_crossplatformOpens and requests the authentication payment windowDevelopment required
returnurlReceives and forwards the authentication resultDevelopment required
payresFinal payment request and result processing pageDevelopment required
cas_noteurlPage that processes virtual account assignment and deposit notificationsDevelopment required
CashReceipt.htmlInformation entry page for cash receipt issuance and cancellationDevelopment required
CashReceiptCash receipt issuance and cancellation request pageDevelopment required
Cancel.htmlInformation entry page for an electronic payment cancellation requestDevelopment required
CancelCancellation request pageDevelopment required
Note The samples in every language use the same input pages (.html). Each feature folder's README.md lists the entry page and what to change.

For the cas_noteurl page that receives virtual account deposit notifications, see Issue and change virtual accounts. For firewall settings, see Firewall and IP information.

    │       └── json_simple.jar
    ├── unified-checkout/
    │   ├── pc/                     payreq_crossplatform, returnurl, payres
    │   └── mobile/                 same files as pc/
    ├── virtual-account/            CyberAccount.jsp, cas_noteurl.jsp
    ├── cancel/                     Cancel.html, Cancel.jsp
    ├── cash-receipt/               CashReceipt.html, CashReceipt.jsp

    ├── card-billing/               CardAuth.html, CardAuth.jsp
    ├── card-billing-window/        CardBillingAuth_Req, returnurl, _Res (+ mobile/)

    ├── acc-cert/                   AccCert.html, AccCert.jsp
    ├── search/                     Search.html, Search.jsp
    └── settlement/                 Settlement.html, Settlement.jsp

The Java samples are organized into feature folders, and each folder's README.md lists what to change. The JSP pages are the same in both packages; only WEB-INF/lib and mall.conf.example differ.

For the library files, see Install the Java library.
