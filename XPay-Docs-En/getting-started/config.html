#Configure conf files

The configuration files are organized as follows. You must pass the absolute path of the lgdacom folder as a parameter when you initialize the XPayClient module.

#File structure

File nameDescriptionTypeMerchant edits
lgdacom/conf/lgdacom.confToss Payments configuration fileConfigurationDo not modify
lgdacom/conf/mall.confMerchant connection settings fileConfigurationModification required
lgdacom/conf/ca-bundle.crtSSL certificate (provided only in the PHP sample)ConfigurationDo not modify
lgdacom/conf/cacerts(Optional) Separate truststore for Java. Not required: if keystore_cacerts_dir is empty, XPayClient 4.1.0.0 uses the default JDK cacerts.Configuration-

#lgdacom.conf

URL connection settings for communicating with Toss Payments.

Caution In lgdacom.conf, you must use only the URLs below.
ParameterTypeURL
urlProductionhttps://xpay-gateway.tosspayments.com/xpay/Gateway.do
test_urlTesthttps://xpay-gateway-sandbox.tosspayments.com/xpay/Gateway.do

#mall.conf

Merchant configuration file for communicating with Toss Payments. Modify it to fit your environment.

ParameterDescriptionValue
server_idIdentifier that distinguishes XPayClient logs from each merchant server when multiple mall.conf files share one log directoryArbitrary identifier for each merchant server
timeoutTimeout for XPayClient requests. A timeout occurs when the request exceeds this time.Integer, in seconds
log_dirDirectory where XPayClient logs are storedFull Path
log_levelLogging threshold. DEBUG shows all logs; other levels show only critical errors.3: INFO, 4: DEBUG
verify_certValidates the SSL certificate. Set this to 0 if a Toss Payments certificate error occurs on the merchant server.0: do not verify, 1: verify
verify_hostValidates the domain name in the SSL certificate0: do not check (test only), 1: check
report_errorWhether to send an error report to Toss Payments when an error occurs0: do not send, 1: send
auto_rollbackWhether to roll back when a payment request exceeds the timeout0: disabled, 1: enabled
output_UTF8Character set of the approval result message. The samples use 1. If omitted, Java 4.1.0.0 uses 1.0: EUC-KR, 1: UTF-8
default_secure_protocolsSettings for TLS 1.2 communicationPHP・ASP・JSP: 2048, .NET: 3072
keystore_cacerts_dirJava only. Path of the truststore (cacerts) used to verify the server certificate. If empty, the default JDK cacerts is used (recommended). If the file at the specified path does not exist, requests fail with response code 20101.Full Path or empty
tx_versionJava only. HttpClient version to use. Applies only to the JDK 1.8–17 build; the JDK 1.7 build always uses 3.x regardless of this value.4: HttpClient 4.x, omitted or any other value: HttpClient 3.x

#Set the merchant ID (MID) and mertkey

At the bottom of mall.conf, you must set the merchant MID configured on the payment page (CST_MID) and its corresponding mertkey.

If you use two or more production MIDs, you can set all MIDs and mertkeys in a single mall.conf file.

#MID rules

Prefixing a production MID with a lowercase t makes it a test MID.

TypeMIDDescription
Productiontest1234Used for live payments.
Testttest1234The production MID with t prefixed.
Caution The mertkey for a production MID is different from the mertkey for its test MID. Do not set them to the same value.

#Find your mertkey

You can find your mertkey in the Toss Payments Developer Center.

  1. Sign in to the Developer Center.
  2. Go to Developer Center > API keys > mertkey.
  3. Find the mertkey value for the MID you want to use.

Test and production values are provided separately.

#Configuration example

Enter values in MID = mertkey format. Lines that start with ; (semicolon) are treated as comments when the configuration file is loaded.

Production and test settings together

ini
; Production MID
test1234 = production mertkey for test1234

; Test MID
ttest1234 = test mertkey for test1234

Multiple MIDs

ini
; First merchant
test1234 = production mertkey for test1234
ttest1234 = test mertkey for test1234

; Second merchant
test5678 = production mertkey for test5678
ttest5678 = test mertkey for test5678

#Security policy for conf and log files

log_dir in mall.conf is the path where payment logs exchanged in approval requests and results of the XPay payment module are stored. mall.conf also stores the production merchant MID and mertkey used for real payments and cancellations.

Caution Never place log_dir or mall.conf in a location accessible from the web. Always use a location that cannot be accessed externally.

#Web-accessible paths

The following paths are accessible from the web, so do not use them for configuration files or log directories.

Development environmentWeb-accessible path
PHP + ApacheUnder DOCUMENT_ROOT
JavaContext Root
ASP, ASP.NET + IISwwwroot and similar
Note If you have no access to paths outside the web-accessible paths (for example, on a shared hosting server), use the API-based Toss Payments payment service instead of XPayClient.

#Troubleshooting

Common configuration file error messages during payment integration.

Error codeCause
10001The user directory setting that points to ~/lgdacom cannot be read or is not set
10002mall.conf file not found
10003lgdacom.conf file not found
20101If the message is SSL setup failed; keystore_cacerts_dir [...] does not exist, the file specified in keystore_cacerts_dir does not exist. Correct the path or leave it empty (Java).
