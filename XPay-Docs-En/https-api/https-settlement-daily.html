#Daily settlement lookup

Direct HTTPS call · servicecode ADJ

Downloads the settlement data for a specified sales date. The response consists of a header line that summarizes the scheduled payout and data lines with settlement details for each transaction.

This feature is called directly over HTTPS without the XPayClient library. Because the call method differs, XPayClient call pattern does not apply.

#Lookup methods

MethodDescription
HTTPS real-time lookupThe merchant server calls the lookup URL and receives the settlement data for the requested sales date. Described on this page.
FTP file deliveryWhen the merchant provides an FTP server, Toss Payments uploads the settlement file on the day after the sales date. A separate agreement is required. See FTP file delivery.

#Request

text
GET https://pgweb.tosspayments.com/pg/wmp/outerpage/trxdown.jsp?mertid={MID}&servicecode=ADJ&trxdate={yyyyMMdd}&key={key}
ParameterRequiredDescription
mertidRequiredMerchant ID. Retrieves all data for the merchant's affiliated stores.
servicecodeRequiredFixed to ADJ
trxdateRequiredSales date to look up (yyyyMMdd). Only sales up to the previous day are available. Lookup by payout date can be arranged by agreement.
keyRequiredMD5 value of the merchant ID concatenated with the mertkey. See Key generation.

#Key generation

text
key = MD5( MID + mertkey )

Look up the mertkey in Find your mertkey. Because the key is created from the mertkey, always call the lookup from the merchant server and never expose the key in a browser or app.

#curl example

This example downloads the settlement data for the sales date September 14, 2026 and saves it to a file.

bash
MID="your MID"
MERTKEY="your mertkey"
TRXDATE="20260914"     # Sales date. Only sales up to the previous day are available.

# key = MD5(MID + mertkey). On macOS, use `md5 -q -s "${MID}${MERTKEY}"` instead of md5sum.
KEY=$(printf '%s%s' "$MID" "$MERTKEY" | md5sum | awk '{print $1}')

curl -sS -G "https://pgweb.tosspayments.com/pg/wmp/outerpage/trxdown.jsp" \
  --data-urlencode "mertid=${MID}" \
  --data-urlencode "servicecode=ADJ" \
  --data-urlencode "trxdate=${TRXDATE}" \
  --data-urlencode "key=${KEY}" \
  -o "${MID}_ADJ_${TRXDATE}.dat"

#Response format

The response consists of a header line (starting with H) and data lines (starting with D), with fields separated by semicolons (;). Usually, one header line and multiple data lines are returned. The delimiter can be changed by agreement.

#Header line (H)

Summarizes the amount and count to be paid out. Consists of 11 fields.

OrderFieldDescription
1TypeH, indicating a header line
2Merchant IDMerchant ID
3Sales dateSales date (yyyyMMdd)
4Scheduled payout dateSales date plus the contracted payout cycle (yyyyMMdd)
5Total transaction countCount of normal transactions (credit card purchases, bank transfers, and so on) + cancellations (credit card purchase cancellations, bank transfer refunds, and so on) + returns (credit card) + cancellation returns (credit card)
6Total transaction amountNormal amount − canceled amount − returned amount + cancellation return amount
7Toss Payments feeFee calculated by applying the fee rate and other terms to the transaction amount. Excludes VAT.
8VAT10% of the Toss Payments fee
9Net amount for the periodTransaction amount − (Toss Payments fee + VAT). Equal to the settlement amount.
10Payout amountUsually equal to the net amount for the period. May differ if there are unpaid amounts or other reasons.
11Unpaid amountSettlement amount − payout amount

#Data line (D)

Per-transaction details that make up the summary amounts in the header. Consists of 11 fields.

OrderFieldDescription
1TypeD, indicating a data line
2Sequence numberData line sequence number
3Merchant IDMerchant ID
4Order IDOrder ID sent by the merchant
5Order dateDate the merchant requested the payment (yyyyMMdd)
6Payment methodSC0010: credit card, SC0030: bank transfer, SC0040: bank deposit, SC0060: mobile phone, SC0070: landline payment, SC0111: culture gift certificate, SC0112: game gift certificate
7Transaction typeTransaction type code applied to settlement for each payment method. See Transaction type codes.
8Transaction amountAmount aggregated into settlement according to the transaction type
9Total feesTotal fees calculated by Toss Payments for the transaction (Toss Payments fee + VAT)
10Sales dateSales date determined at settlement (yyyyMMdd)
11Payout datePayout date determined at settlement (yyyyMMdd)

#Key points

  • The net amount for each transaction is transaction amount − total fees. A positive result is a payout; a negative result is a deduction.
  • If you also use the escrow service, the response for the same sales date can contain multiple header lines. Check the payout date for each transaction in the payout date field of the data line, not in the header.
  • If the payout amount differs from the net amount for the period, check the unpaid amount field.
  • Only sales up to the previous day are available. Look up today's sales the next day.

#FTP file delivery

Merchants that can expose an FTP server can receive files instead of querying over HTTPS. This requires a separate agreement with Toss Payments.

ItemDescription
Generation scheduleSends a file for the sales date once, at 7:00 AM on the day after the sales date.
File nameMIDSettlementDate.dat. Example: tossmid20260914.dat
File formatSame as Response format.
Storage locationPath specified by the merchant. If not specified, the home directory of the FTP account.

Provide your FTP server information (IP, account, password, and path) to Toss Payments, and register all of the source (Toss Payments server) IPs below in your firewall and ACL so that they can connect.
