#Daily transaction lookup

Direct HTTPS call · servicecode TRX / REV

Downloads the approvals (TRX) or cancellations (REV) for a specified date. You can retrieve data for any date when needed to reconcile with your merchant system or to power lookup features.

This feature is called directly over HTTPS without the XPayClient library. Because the call method differs, XPayClient call pattern does not apply.

#Lookup methods

MethodDescription
HTTPS real-time lookupThe merchant server calls the lookup URL and receives the data for the requested date. Described on this page.
FTP file deliveryWhen the merchant provides an FTP server, Toss Payments uploads data files periodically. A separate agreement is required. See FTP file delivery.

#Request

text
GET {lookup URL}?mertid={MID}&servicecode={TRX|REV}&trxdate={yyyyMMdd}&key={key}
EnvironmentLookup URL
Service (live merchant ID)https://pgweb.tosspayments.com/pg/wmp/outerpage/trxdown.jsp
Test (test merchant ID)https://pgweb.tosspayments.com/pg/wmp/testadmin/outerpage/trxdown.jsp

In the test environment, call with the test merchant ID (the merchant ID prefixed with t) and its mertkey.

ParameterRequiredDescription
mertidRequiredMerchant ID
servicecodeRequiredLookup type. TRX: approvals, REV: cancellations
trxdateRequiredLookup date (yyyyMMdd). Transaction date for TRX, cancellation date for REV.
keyRequiredMD5 value of the merchant ID concatenated with the mertkey. See Key generation.

#Key generation

text
key = MD5( MID + mertkey )

Look up the mertkey in Find your mertkey. Because the key is created from the mertkey, always call the lookup from the merchant server and never expose the key in a browser or app.

#curl example

This example downloads the approvals for September 14, 2026 and saves them to a file. For cancellations, change SERVICECODE to REV. For the service environment, change URL to the service lookup URL.

bash
MID="your MID"
MERTKEY="your mertkey"
SERVICECODE="TRX"      # TRX: approvals, REV: cancellations
TRXDATE="20260914"
URL="https://pgweb.tosspayments.com/pg/wmp/testadmin/outerpage/trxdown.jsp"   # test
# URL="https://pgweb.tosspayments.com/pg/wmp/outerpage/trxdown.jsp"           # service

# key = MD5(MID + mertkey). On macOS, use `md5 -q -s "${MID}${MERTKEY}"` instead of md5sum.
KEY=$(printf '%s%s' "$MID" "$MERTKEY" | md5sum | awk '{print $1}')

curl -sS -G "$URL" \
  --data-urlencode "mertid=${MID}" \
  --data-urlencode "servicecode=${SERVICECODE}" \
  --data-urlencode "trxdate=${TRXDATE}" \
  --data-urlencode "key=${KEY}" \
  -o "${MID}_${SERVICECODE}_${TRXDATE}.dat"

#Response format

The response is text with one record per line and fields separated by semicolons (;). The field order is shown in the table below. Fields and the delimiter can be changed by agreement.

#Approvals (TRX)

Includes only successful payments; failed transactions are excluded.

OrderFieldFormatDescription
1midVARCHAR2(15)Merchant ID
2paytypeCHAR(6)Payment method code. SC0010: credit card, SC0030: bank transfer, SC0040: bank deposit, SC0060: mobile phone, SC0111: culture gift certificate, SC0112: game gift certificate
3transactionVARCHAR2(24)Toss Payments transaction ID (TID)
4oidVARCHAR2(64)Order ID
5financecodeVARCHAR2(10)Financial institution code. Same as the value received at payment.
6financenameVARCHAR2(10)Financial institution name
7buyeridVARCHAR2(30)Buyer ID
8amountNUMBERTransaction amount
9useescrowCHAR(1)Final escrow status. Y: applied, N: not applied
10paydateyyyyMMddHHmmssPayment date and time. Transaction time for cards, transfer time for bank transfers, and deposit time for bank deposits.
11authnumberVARCHAR(8)Approval number
12statusCHAR(2)Transaction status. 10: transaction succeeded (11, failed transaction, is excluded from the lookup.)

#Cancellations (REV)

Includes all transactions whose cancellation or refund was requested on the lookup date, showing their final status on that date.

OrderFieldFormatDescription
1midVARCHAR2(15)Merchant ID
2paytypeCHAR(6)Payment method code. Same as in the approval data.
3transactionVARCHAR2(24)Toss Payments transaction ID (TID)
4oidVARCHAR2(64)Order ID
5financecodeVARCHAR2(10)Financial institution code
6financenameVARCHAR2(10)Financial institution name
7buyeridVARCHAR2(15)Buyer ID
8amountNUMBERCancellation amount for cards; refund amount for bank transfers and virtual accounts
9useescrowCHAR(1)Final escrow status. Y: applied, N: not applied
10refunddateyyyyMMddHHmmssFor cards, the cancellation request date and time (before or after purchase); for bank transfers and virtual accounts, the refund completion date and time; for mobile phones, the cancellation date and time
11authnumberVARCHAR(8)Approval number
12statusCHAR(2)Cancellation status. 20: cancellation or refund succeeded, 21: cancellation or refund failed

#Key points

  • A transaction canceled on the day of payment appears twice: once in the approvals and once in the cancellations.
  • Status 21 (failure) in the cancellations appears only when a refund request for a payment method other than credit card fails. If a credit card cancellation before purchase fails, Toss Payments forcibly cancels it early the next morning, so it appears as 20. Bank transfers and virtual accounts include only successful cancellations, so they show only 20.
  • For transactions without an approval number, such as bank transfers, authnumber is returned as 0.
  • The default date format is yyyyMMddHHmmss. By agreement, you can receive the YYYY-MM-DD HH:MM:SS format.
  • When reconciling, match by transaction ID (transaction). Even for the same order ID, approvals and cancellations appear on separate lines.

#FTP file delivery

Merchants that can expose an FTP server can receive files instead of querying over HTTPS. This requires a separate agreement with Toss Payments.

ItemDescription
Generation scheduleSends the cumulative data for the current day every 20 minutes (at 5, 25, and 45 minutes past each hour). At 00:05, sends the complete data for the previous day.
File nameMID_TypeCode_TransactionDate.dat. The type code is AUTH for approvals and REV for cancellations. Example: tossmid_AUTH_20260914.dat
File formatSame as Response format. FTP files also include payment method SC0070 (landline payment).
Storage locationHome directory of the FTP account provided by the merchant

Provide your FTP server information (IP, account, password, and path) to Toss Payments, and register all of the source (Toss Payments server) IPs below in your firewall and ACL so that they can connect.
