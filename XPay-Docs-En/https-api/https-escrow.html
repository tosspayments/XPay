#Escrow

Direct HTTPS call · Shipping information registration · Delivery completion registration · Result notifications

Escrow is a system in which payment funds are held by a third party until the buyer receives the product. Toss Payments provides escrow for bank transfers and virtual accounts. To receive settlement for escrow payments, the merchant must complete shipping information registration or delivery completion registration.

This feature is called directly over HTTPS without the XPayClient library. Because the call method differs, XPayClient call pattern does not apply.

#Escrow flow

Each step can be handled through the API, the email sent to the buyer, or the merchant admin. This page describes shipping information registration and delivery completion registration through the API, and receiving results such as purchase confirmations and purchase cancellation requests.

#Choose a registration method

MethoddlvtypeWhen to useWhat happens next
Shipping information registration03When you ship with a carrier listed in Courier codesDelivery is tracked automatically with the tracking number and marked as completed when the delivery finishes.
Delivery completion registration01When the item is delivered without a carrier code or tracking number (quick service, in-house delivery, pickup by the buyer, and so on)Registers the actual receipt information instead of carrier and tracking information.

#Request

Both methods send parameters to the same URL. The sample calls it with a POST in application/x-www-form-urlencoded format.

EnvironmentURL
Productionhttps://pgweb.tosspayments.com/pg/wmp/mertadmin/jsp/escrow/rcvdlvinfo.jsp
Testhttps://pgweb.tosspayments.com:9091/pg/wmp/testadmin/jsp/escrow/rcvdlvinfo.jsp

#hashdata generation

The MD5 value (32 lowercase hexadecimal characters) of the following values concatenated in order. Note that the two methods use different combinations.

text
Shipping information registration (03): MD5( mid + oid + dlvdate + dlvcompcode + dlvno + mertkey )
Delivery completion registration (01):  MD5( mid + oid + dlvtype + rcvdate + mertkey )

Shipping information registration does not include dlvtype, while delivery completion registration includes dlvtype (01). Look up the mertkey in Find your mertkey, and always make the call from the merchant server.

#curl example (shipping information registration)

This example registers shipping information in the test environment for an order shipped with CJ Logistics.

bash
# Test. For production, use https://pgweb.tosspayments.com/pg/wmp/mertadmin/jsp/escrow/rcvdlvinfo.jsp
SERVICE_URL="https://pgweb.tosspayments.com:9091/pg/wmp/testadmin/jsp/escrow/rcvdlvinfo.jsp"

MID="your MID"
MERTKEY="your mertkey"
OID="order ID"
DLVDATE="202609141525"     # Shipping date and time, yyyyMMddHHmm
DLVCOMPCODE="CJ"           # Carrier code (CJ Logistics)
DLVNO="123456789012"       # Tracking number

# hashdata = MD5(mid + oid + dlvdate + dlvcompcode + dlvno + mertkey). On macOS, use `md5 -q -s "..."`.
HASHDATA=$(printf '%s' "${MID}${OID}${DLVDATE}${DLVCOMPCODE}${DLVNO}${MERTKEY}" | md5sum | awk '{print $1}')

curl -sS -X POST "$SERVICE_URL" \
  --data-urlencode "mid=${MID}" \
  --data-urlencode "oid=${OID}" \
  --data-urlencode "dlvtype=03" \
  --data-urlencode "dlvdate=${DLVDATE}" \
  --data-urlencode "dlvcompcode=${DLVCOMPCODE}" \
  --data-urlencode "dlvno=${DLVNO}" \
  --data-urlencode "hashdata=${HASHDATA}"

# Response: OK on success, FAIL : error message on failure

#Response

ResultResponse body
SuccessOK
FailureFAIL : error message

Treat the request as successful only when the response body, with leading and trailing whitespace removed, is OK.

#Receive results

You can receive receipt confirmations and purchase cancellation requests made by the buyer from the email, as well as carrier delivery completion results after shipping information registration, on a merchant page and apply them to your merchant system.

#Register the receiving URL

Send the types of results you want to receive and the receiving URL to techsupport@tosspayments.com, and Toss Payments registers them. You can set only one URL, and all results are sent to the registered URL.

ResulttxtypeWhen sent
Receipt confirmation resultCWhen the buyer confirms receipt from the email after delivery is completed
Purchase cancellation requestRWhen the buyer requests purchase cancellation from the email after delivery is completed
Carrier delivery completedSWhen delivery completion is confirmed in the carrier's tracking data after shipping information registration
N/C processing completedNWhen Negative Confirm processing is completed

#hashdata verification

Create the MD5 value of the received values concatenated in the following order and compare it with hashdata. Use the received values for ssn, ip, and mac (.) as is.

text
MD5( mid + oid + tid + txtype + productid + ssn + ip + mac + resdate + mertkey )
java
String src = mid + oid + tid + txtype + productid + ssn + ip + mac + resdate + mertkey;
byte[] digest = java.security.MessageDigest.getInstance("MD5").digest(src.getBytes());

StringBuilder hash = new StringBuilder();
for (byte b : digest) {
    hash.append(String.format("%02x", b & 0xff));
}

if (hash.toString().equals(hashdata)) {
    // Verified: apply the result to the merchant system, then output "OK"
} else {
    // Verification failed: log it, check the cause, and output a value other than "OK"
}

#Response and retries

If you applied the result successfully, respond with OK only. If Toss Payments does not receive the result successfully, it resends it up to 10 times at 30-minute intervals.

Caution Even if the merchant processed the result successfully, the same result can be sent again if the response does not reach Toss Payments. Check oid, tid, and txtype to see whether you already applied the result, and avoid applying it twice.

#Key points

  • Escrow payments are not settled unless you complete shipping information registration or delivery completion registration.
  • Determine whether a registration API call succeeded by checking that the response body is exactly OK.
  • Do not output HTML tags or scripts on the result receiving page. If the response contains other content, correct operation is not guaranteed.
